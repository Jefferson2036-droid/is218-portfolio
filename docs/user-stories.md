# User stories

Reader: an early-career reviewer for applied data/AI roles in any industry (see reader.md). Retargeted 2026-11-23.

1. **First look.** As a hiring manager, I want to see within 30 seconds what kind of work Jefferson wants and his strongest project, so I can decide whether to keep reading.
   - Accept: the first screen shows my name, the kind of work I want (building data and AI tools with the people who use them, forward-deployed style), and one featured project with a one-sentence result, a "try it" link and a "code" link; it works on a phone.

2. **Case study.** As a hiring manager, I want each project told as problem → what I built → how I checked it, so I can judge how I handle a real problem.
   - Accept: every project page has those sections, says what I did personally versus my team, links to commits or tests, and states what was not checked.

3. **Fit check.** As a reviewer, I want the skills that applied data/AI postings ask for matched to proof, so I can check fit quickly.
   - Accept: a home-page strip lists the skills the three captured postings share (research/job-sources.md), grouped under the two areas (data and AI in a business setting; customer-facing builds); each row links to a repo, file or demo; skills I don't have yet are listed as "learning," not hidden.

4. **Phone reading.** As a recruiter reading on a phone between meetings, I want the site to load fast and fit the screen, so I don't give up.
   - Accept: no sideways scrolling at 375 px wide; images are compressed; checked in a phone-size browser window before each publish.

5. **Contact.** As a recruiter, I want to reach Jefferson or see his résumé in one click, so I can move him forward.
   - Accept: LinkedIn, GitHub and email links in the header and footer; the résumé opens as a PDF.
